# Design-to-Implementation Review

A structured handoff review for finding the gaps between a polished screen and a buildable, testable product experience.

Use it before implementation, during design QA, or when a team is experiencing repeated ambiguity between design and engineering.

## Input

Provide any available design context:

- Screenshot or Figma link
- Component or feature description
- Existing design-system guidance
- User flow or prototype
- Handoff notes
- Product constraints

The skill can work from a static screenshot, but it should clearly state which behaviour cannot be inferred from one.

## Output

The review returns:

1. An implementation-readiness assessment
2. Prioritised gaps and clarification questions
3. Component and interaction contracts
4. Responsive and accessibility considerations
5. Testable acceptance criteria
6. One next action to unblock delivery

## What it does not do

- Generate production code
- Invent design tokens, breakpoints, business logic, or API contracts
- Demand exhaustive documentation for trivial UI
- Treat visual similarity as proof of implementation quality
- Replace design critique, engineering review, or accessibility testing
